# ExamCrafter 與模型轉接槽

2026-10-14 整合 https://github.com/Shawn-afk-afk/------ ，使用當日取得的 main 版本 b698652。網站維持知序的登入、權限、資料庫與 98.css 外觀；原專案核心引擎位於 backend/vendor/examcrafter，整合邏輯位於 backend/exam_studio.py。原始獨立 FastAPI 服務不需另外啟動。

## 操作入口

管理者登入 http://127.0.0.1:8765/，側欄新增「教材出題工作室」和「模型轉接槽」。原評量、組卷、白板與批改流程照常使用。

工作室流程：選擇科目 → 勾教材 → 配置大題與配分 → 本機生成 → 審題修改 → 匯出或送入題庫。

* 教材磁碟支援 PDF／DOCX／TXT／MD 與貼上文字。每份文件上限 8 MB、PDF 上限 150 頁；掃描檔沒有足夠文字層時須先 OCR 或貼文字。封存單元保留先前出題快照。
* 已載入 ZJU 第一／二章 11 個分節單元。分節依 PDF 標題解析，附章節 PDF 頁範圍，仍需核對。LLM 模式只接受這兩章的來源；允許概念延伸至實作，但模型生成內容及其符合要求的程度需人工確認。
* 題型包含單選、概念填答、改寫／除錯說明、翻譯及閱讀題組。閱讀題組可放程式碼或案例。一次最多 40 題，第一輪建議 1–3 題確認品質，再擴大生成。
* 舊卷骨架支援 PDF／DOCX，會建立背景解析工作；完成後可套用到大題配置。題數、配分需教師確認；模型失敗時不補造一份假骨架。
* 所有生成題都是草稿，審題頁提供正解、完整詳解及 LLM 題的來源段落。來源編號由後端核對本次教材快照，並保存原文；這能確保來源可追溯，不能代替教師核對答案正確性。
* 可匯出試題卷、學生作答紙、教師詳解三份 DOCX。LLM 考卷可以送入原題庫成為待覆核的新題，核准後才可分配；防止重複匯入。匯入後從原題庫建立修改版本，工作室考卷鎖定編輯，既有 Word 仍可下載或重新匯出。
* 英文科的一般單選題沿用原專案抽換、圖片題／文字題轉換與圖表引擎；每次建立新的工作版本。這條圖表管線目前不適用 LLM 題或閱讀子題。LLM 題可人工修改或重新生成大題。

## 三個模型槽

| 模型槽 | 目前預設 | 用途 |
| --- | --- | --- |
| 教材出題 | gemma4:12b-it-q4_K_M | 新題、舊卷骨架、英文題抽換 |
| 白板看圖與追問 | gemma4:12b-it-q4_K_M | iPad 白板影像與協作追問 |
| 正式批改 | gpt-oss:20b / medium | 分項批改與作答證據 |

原批改及白板設定在尚未手動綁定模型槽時仍有效。模型槽支援 Ollama，以及 localhost 上的 OpenAI 相容 chat/completions 服務；目前網址限 localhost／127.0.0.1／::1。後續搬到 M5 Max 可以在新主機啟動對應服務。相容 API 的 JSON 與圖像能力仍需用實際服務試跑。

新增來源可以填顯示名稱、基底模型、LoRA 版本備註、服務網址、服務提供的模型名稱及視覺能力。保存來源不會立刻切換；按核對並切換時必須確認模型確實由該服務提供。尚未上傳或尚未載入的 LoRA 可以先登錄，不能偽裝成已就緒。出題與白板工作保存當次來源設定，後來切換不會改掉已排隊工作的來源。

## 接入之後的 LoRA

這個槽負責推論來源切換，不負責訓練或自動合併權重。收到檔案後需核對 adapter_config、訓練時的基底、權重格式、tokenizer 與視覺模組。

LoRA 必須搭配訓練時相容的基底版本，不能把 e4b 的 adapter 直接當作 12B 的 adapter。可用的接法是：由支援該 Gemma 版本的本機服務載入基底與 adapter，或先合併／轉換成受支援的模型後登錄到 Ollama；實際選哪種方式要等檔案及執行環境到齊。不要假設只改名稱就完成權重載入。

相關接口參考：[Ollama 模型匯入](https://docs.ollama.com/import)、[本機相容 API](https://docs.ollama.com/api/openai-compatibility)。目前未取得你的 LoRA，尚未驗證該權重或在 M5 Max 執行。

## 資料與測試

原文文件、解析索引、教材快照、出題請求、模型來源、結果、人工修改之前的版本及三份 Word 均保存於 backend/assessment.sqlite3。原專案的 JSON 快取和未驗證的任意下載路徑不作為對外入口。本機模型失敗不會自動使用付費雲端，也不把原專案的示意選項補入有效考卷。

依賴：python-docx、pdfplumber、Matplotlib。這台電腦的 Matplotlib 已安裝於 .runtime/packages。其他環境執行 `python -m pip install -r requirements-exam.txt`。

測試使用隔離 QA 資料庫。已完成 Gemma 4 12B 真實題目生成、來源回查、瀏覽器三份 Word 匯出與送入待覆核題庫。自動測試另外涵蓋模型槽切換、未提供模型拒絕啟用、相容 API 圖像格式、英文圖片題轉換與 DOCX 嵌圖、權限及既有 WSL2 沙箱。這些測試不表示每種生成內容都正確；舊卷骨架及實際 LoRA 仍需使用目標資料確認。

搬至 macOS 時不要複製 Windows 的 .runtime/packages；在新環境重新安裝 requirements-exam.txt。正式 Python 批改仍需另外處理 Linux 隔離執行環境。
