# iPad AI 協作白板試跑

這是第一輪功能測試：iPad 在瀏覽器手寫、畫圖或輸入文字；白板快照、作答、AI 對話與分析保存於本機 SQLite。辨識與批改均呼叫主機上的 Ollama，iPad 不需安裝 Python 或模型。介面延續 98.css。

## 管理者準備

1. 本機開啟 http://127.0.0.1:8765/，使用自己的管理者帳號。
2. 題庫搜尋 `LAB-AI-001`、`LAB-AI-002`、`LAB-AI-003`。先看中文詳解、獨立題、規準及教材來源，再核准。正式資料庫這三題仍為待覆核；測試帳號及測試分配只存在隔離 QA 資料庫。
3. 建立組員帳號與一份測試評量，挑選核准的白板題，分配給測試者。第一輪建議只分配一題，避免等待過久。
4. 設定頁確認文字批改模型 `gpt-oss:20b` 與白板視覺模型 `gemma4:12b-it-q4_K_M`。兩者角色不同；gpt-oss 不接收白板影像。白板題即使有 AI 分數也需人工覆核發布。
5. 若兩台裝置不同網路或網路未確定，使用 ngrok HTTPS 入口。在本機執行 `scripts/Start-Tunnel.ps1`，網址透過 http://127.0.0.1:4040/api/tunnels 查詢。現有腳本會尋找 PATH 或 `.runtime/tools/ngrok.exe`，讀取使用者已設定的 ngrok 憑證，不把 token 寫進程式。

## 三題與教材範圍

| 題號 | 任務 | 概念來源 | 獨立階段 |
| --- | --- | --- | --- |
| LAB-AI-001 | 英文 MLM 程式閱讀與標註錯誤 | 第二章預訓練目標；從概念延伸至標籤實作 | next-token 位移與 padding 檢查 |
| LAB-AI-002 | 畫 encoder-decoder、Q/K/V 與 cross-attention | 第二章架構與注意力 | 區分未來目標遮罩與 encoder 來源可見範圍 |

題目是依第一／二章概念原創的實務延伸，不是假稱組員做過的實驗。共 64 題的最新原創題目版本為中文 32、英文 32；本次三題預設為草稿，每題 12 分。

## 測試者操作

1. iPad 使用 Safari 開啟當次 HTTPS 網址，登入分配的帳號。若 ngrok 顯示普通免費服務提示，可按 Visit Site。
2. 開始評量，先寫「初稿理由」，再畫圖或標註程式碼。工具包含筆、橡皮擦、框線、箭頭、文字、復原與重做。文字標籤可鍵盤或 iPad Scribble 輸入；點畫布放置，也可用放置按鈕。
3. 使用 Apple Pencil 時可勾「只接受觸控筆」，避免手掌／手指畫線。實際 Pencil 辨識、掌壓與 Safari 行為須以真實 iPad 驗證。這版沒有筆壓效果、雙指縮放或離線作答。
4. 等候「白板已保存於主機」，輸入想核對的問題，再按 AI 檢查。每題最多四次成功／進行中的請求；推論排隊期間可繼續記錄修改理由。第一次 AI 請求後初稿鎖定。模型失敗會顯示錯誤，可再次請求。
5. 核對 AI 的轉錄與追問。可載入轉錄、修正誤讀，再勾已確認；AI 框線屬於提示，不會寫入學生筆跡。說明接受／拒絕提示的理由。
6. 按「完成協作，進入獨立作答」。此時白板與本題 AI 關閉，才顯示另一個小情境。完成獨立回答後繳交整份評量。退出前確認保存狀態；網路中斷時不要立即關閉或重新整理。
7. 管理者在批改頁按「檢視白板與 AI 過程」，對照初稿、歷次快照、對話、獨立答案及分項證據。必要時修改分項分數；確認後發布。重新開放會建立新作答版本，保留舊歷程。

## 已驗證與這輪要觀察的項目

已驗證：本機視覺模型處理實際網頁白板快照；英文標註與程式碼轉錄成功，第一輪約 69 秒，並以中文追問。這是單次測量，包含當次載入與排隊，不能視為效能承諾。已驗證瀏覽器滑鼠筆跡輸入、恢復初稿／快照／獨立回答、後端階段鎖定、未登入及跨學生權限；16 項自動測試全部通過，包含 WSL2 執行。真實 gpt-oss:20b 分階段評分約 25 秒（當次模型已載入），完整三題繳交與待覆核流程也已通過，另外兩題空白回答正確記為 0 分。測試曾發現跨階段引用，已加入後端拒絕檢查與回歸測試；AI 評語仍需教師覆核。

真人試跑需記錄：iPad 型號／Safari 版本、網路、Pencil 筆跡是否流暢、文字誤讀、圖中箭頭誤讀、等待時間、重進後是否恢復、學生是否能指出 AI 錯誤、獨立回答是否仍正確。AI 可能看錯或給過多提示，教師必須核對實際圖像；不能只依評分推斷學生是否認真或其人格。

免費本地模型不需付推論費；ngrok 免費方案有流量與使用額度限制。模型本地運算，但 ngrok 用於網站傳輸，瀏覽器 Python 練習首次載入也可能需要網路。電腦、Ollama 與通道在測試期間保持運作；模型端口 11434 不對外公開。

## 未來移至 M5 Max

網站與白板使用 Python、SQLite、瀏覽器 Canvas 和 Ollama HTTP 接口。環境變數 `ASSESSMENT_OLLAMA_URL` 可指定新主機的本地接口；預設為 `http://127.0.0.1:11434`。備份資料庫會包含白板 PNG、筆跡、題庫、來源、歷程與設定，轉移前先執行 `scripts/Backup-Database.ps1`。

Windows 的 PowerShell 啟動腳本及 WSL2 正式程式沙箱不能直接搬到 macOS。Mac 網站可用 `python3 backend/server.py --port 8765` 啟動，但正式 Python 批改需另接隔離 Linux 執行環境，或完成 Mac runner 改寫及隔離驗證。M5 Max 的模型容量、速度、實際裝置相容性尚未測試；不能將 Windows 本次速度當作 Mac 的預估。
